# Calibration data

The published results are calibrated on a **synthetic digital twin** generated by
`carnot.calibration.generate_twin`. No measured charging-session data from a UAE operator were
available to this study, so the calibration validates the estimation procedure and parameter
identifiability, not the absolute accuracy of the physical parameters. This is stated in the report.

## Substituting real field data

Provide a single CSV with one row per observation sample:

| column | unit | meaning |
|---|---|---|
| `session` | – | integer session identifier |
| `t_s` | s | seconds since plug-in |
| `day` | – | integer day identifier (used for grouped train/test splits) |
| `t_amb` | °C | ambient air temperature at the charger |
| `g_cab` | W/m² | plane-of-array irradiance on the cabinet |
| `wind` | m/s | wind speed |
| `power` | kW | measured DC power |
| `soc` | – | state of charge (0–1) |
| `t_cab` | °C | cabinet / power-electronics temperature |
| `t_bat` | °C | pack temperature |

Required minimum for the 7-parameter fit: ~12 sessions spanning at least four distinct days, with
at least one day above 42 °C. Sampling at 30–60 s is sufficient; the loader interpolates onto the
model grid.

To use it, set `calibration.data_path: data/calibration/field_sessions.csv` in
`config/default.yaml`. `experiment_calibration` will then fit the real data instead of generating a
twin. Everything downstream (residual learner, black-box comparison, figures) is unchanged.

## Why a twin at all

A twin makes the calibration falsifiable: the truth is known, so we can measure recovery error and
identifiability rather than assert that the fit "looks good". The multipliers used to create the
twin are declared in `src/carnot/calibration.py::TRUTH_MULTIPLIERS`.
